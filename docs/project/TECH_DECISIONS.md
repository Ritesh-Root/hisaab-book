# Hisaab — Technical Decisions

## TD-1: Deterministic core, LLM as optional layer

**Decision**: the reconciliation pipeline produces the complete correct result
with zero external calls; `OPENAI_API_KEY` only enables enrichment (narratives,
unknown-format schema mapping).

**Context**: the deployed demo link must work throughout evaluation with no
credentials, and a 3-minute demo video cannot tolerate an API outage. But this
is an AI-agent hackathon — a pure script is not the point.

**Trade-off**: slightly more code (templates + LLM paths). Bought: a demo that
cannot die on stage, and an honest "AI where it earns its place" story.

## TD-2: Evidence-gate verification instead of vibes

**Decision**: every finding candidate is re-checked against its cited raw CSV
rows (claimed amount and UTR must literally appear) before publication;
failures are dropped, not annotated.

**Context**: Codex-hackathon winners (Pune's Touchstone "data lie detector",
FORGE's eval gate, OpenAI HQ's Rippletide decision layer) share one trait — a
system that *decides selectively* rather than generating freely. A
reconciliation tool that hallucinates a dispute is actively harmful.

**Trade-off**: a real finding with mangled evidence is silently dropped.
Acceptable: evidence is generated by the same code path, so mismatches mean a
real bug we want surfaced in tests, not papered over.

## TD-3: TanStack Start server fns over a separate API

**Decision**: keep one deployable; `reconcileFiles` is a `createServerFn`.

**Context**: template started as TanStack Start; a separate Express/API server
would double deploy surface for zero benefit at this scale.

## TD-4: Seed data generated by script, committed alongside

**Decision**: `scripts/gen-seed.ts` (seeded LCG, no `Math.random`) writes the
four sample CSVs; both script and output are committed and byte-reproducible.

**Context**: tests and the demo depend on the exact ₹4,200 story (missing
···8842, unsettled ···2210, duplicate ···5517). Reproducibility makes test
failures debuggable.

## TD-5: Mock deleted, not kept as fallback

**Decision**: `src/lib/hisaab/mock.ts` removed when the engine landed; the UI
has one data path.

**Context**: the viability gate checks "repository matches what was demoed".
Two data paths invites drift and reads as unfinished.
